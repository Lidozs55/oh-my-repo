# 护栏与上下文治理：让约束真正生效

> 何时读我：要把某条「必须」变成真约束（沙箱、权限、hooks、pre-commit、CI），不知道放哪一层时；规则文件（AGENTS.md / CLAUDE.md）越写越长、遵守率越来越低，想做减法时；要为 AI 编码搭第一道门禁（自动格式化、危险操作拦截、依赖核实）时；长会话或 compact 之后 AI 忘掉约定，要把关键约束挪出对话层时；怀疑新依赖是模型编造的包名，或担心 secrets、一次性脚本混进仓库时；评审 AI 产出的代码，要划分「哪些约束归机器管、哪些归人管」时。

本文件回答一个问题：**约束写在哪里，才不依赖模型「愿意遵守」。** 三层治理（流程门 > 独立评审 > 规则文本）之所以成立，前提是每层背后有对位的护栏兜底。

## 一、强制性阶梯：先决定约束住在哪一层

| 强 | 层 | 机制本质 | 怎么失效 |
|---|---|---|---|
| 1 | 操作系统沙箱 / 权限系统 | 进程边界：断网、文件只读、容器无凭据 | 内核级突破 |
| 2 | 工具钩子阻断 | 宿主在工具执行前后强制回调，可拒绝动作 | 钩子超时、fail-open 配置错误 |
| 3 | CI / pre-commit 拒绝 | 在模型上下文之外运行，拒绝提交或合并 | 本地 `--no-verify` 绕过且 CI 未兜底 |
| 4 | 人工审批门 | 方案、契约、高危路径按风险分级须人点头 | 依赖人真的看 |
| 5 | lint / 测试反馈环 | 失败自动回喂 agent 循环，迫使其自修 | 收到反馈仍不修（可再迭代） |
| 6 | 流程 skill（含本 Skill） | 结构化流程引导，靠模型自主遵循 | 未被触发或中途偏离 |
| 7 | 规则文件 | 常驻提示，概率性遵守 | 长会话稀释、compact、规则互相冲突 |

一句话原则：**提示是请求，钩子是保证。** 放置判据只有一问：这条约束是「绝对不能发生」，还是「发生了要立刻被纠正」？前者必须住进 1-3 层；后者放 4-5 层；只是偏好与事实才留在 6-7 层。关乎正确性的「必须」停在 7 层，等于没说。

判断类约束（命名是否恰当、抽象是否过早、该不该提问）没有确定性通道——钩子读不懂语义，正则冒充不了判断。它们的兜底是独立评审：隔离上下文的评审者逐项给出四值判定（符合 / 违反 / 未涉及 / 证据不足），第四值让评审者能坦白「没查实」，而不必在两个硬答案里硬挑一个。做法是把可机械判定的部分拆出来上钩子，其余交给独立评审，不要为语义配正则。

同时记住：没有哪一层是银弹。每轮重注入的硬约束在超长会话中仍可能失守——可靠性来自多层冗余加关键节点人审，而不是某一层的完美。

## 二、规则文件治理：少而硬，导航为主

AGENTS.md / CLAUDE.md 这类规则文件是发给 AI 的操作规程，不是攒心愿的地方：

- **总量设卡**：硬规则封顶 12 条、全文压在 200 行以内；宁肯条文少而条条咬人，不养一大排从未生效的摆设。
- **条条挂事故**：每条写成可判对错的命令句，且必须对得上一次真实翻车——说不出「这条拦的是哪回事故」的，直接裁掉。
- **导航为主**：大部分篇幅应是事实与路标（构建/测试命令、目录结构、规范文档在哪），不是禁令。导航解决「不知道」，禁令解决「不做」；让前者挤占后者的注意力，两头都输。
- **措辞要能验**：写「提交前跑 lint」这种真伪立判的句子，别写「务必上心」这类无法验证的叮嘱——后者只是白占注意力。
  对照：「出错要妥善处理」留不下任何记忆；「外部调用失败必须写 error 日志并原样抛出」一查便知真假。
  两条规则打架时模型会一起无视；示例要节制——样例贴得太近，模型会照抄样例的表面特征而不去领会规则本身。
- **只在重复犯错后加规则**：预防性堆规则是负收益；新规则应覆盖现有规则未覆盖的失误模式，而不是换种说法重写一遍。
- **人维护、AI 只提议 diff**：可让 AI「基于本次会话的纠正」起草修改建议，但合入必须过人眼；让 AI 直接治理规则文件，趋势必然是只增不减。
- **定期腐烂检测**：逐条问「这条引用的代码/流程还存在吗」。指向已删函数、已换命令的旧规矩直接删；留下的每条补一句「为什么存在」。只加不减的规则文件必然腐烂。
- **来源可信**：从网上复制的规则文件视为不可信输入——它本身可以是提示注入的载体。

## 三、供应链护栏

- **新依赖先核实再引入**：模型会编造看起来合理的包名（依赖幻觉），攻击者会抢注同名包投毒（slopsquatting）。任何新包名必须对照官方 registry 核实存在性与维护者；CI 扫 lockfile / manifest 的 diff，白名单之外的包名直接拒绝。核实靠字符串级校验，不靠「模型读了好规则就会自己查」。
- **secrets 不落库**：.env 与凭据文件进 ignore；提交前跑 secret 扫描；agent 输出中的令牌要掩码。凭据进了 git 历史，轮换远比删除可靠。
- **一次性脚本不进生产依赖**：迁移、验证、演示脚本放 scripts/ 一类隔离目录并排除出打包清单；它们引来的临时依赖不写入生产依赖表。生产清单里每个包都应能回答「谁在运行时用它」。

## 四、上下文治理速查

总原则是上下文外置：该常驻的极简，该持久的落盘，该强制的出层。

- **token 经济**：常驻上下文的每一行，无论相关与否都持续付费。常驻的必须极简；细节走「索引 + 正文」两层——入口常驻、正文按需加载。文件在变大之前就拆，别等维护不动。
- **记忆外置**：执行台账（决定了什么、为什么、错了的代价）与纠正记录写进文件，关键结论不依赖会话记忆。不存在「恢复会话」——恢复等于重读台账，再与 git log 对账。
- **compact 会丢对话层**：压缩之后，写在对话里的叮嘱与临时约定会被降权或遗忘；hooks 与 CI 的配置住在上下文之外，不受影响。某条约束若 compact 后总失效，别打磨措辞，直接换层——搬进 1-3 层。
- **会话预算**：收尾与否由行为信号定，不由占用比例定——同一个问题问了第二遍、刚读过的文件又去翻、先前说定的约束开始记不清，任何一条冒头就收尾并靠台账续接（占用比例只当参考线）；代码库与文档变大后幻觉随之增多，定期开新会话。

## 附录：三个最小护栏配方（宿主差异已标注）

**配方 A｜写后自动格式化**——Claude Code PostToolUse；宿主无关等价物：编辑器 format-on-save + CI formatter 检查。

```json
{ "hooks": { "PostToolUse": [{
  "matcher": "Edit|Write",
  "hooks": [{ "type": "command", "command": "fmt-on-save.sh",
              "timeout": 15 }]
}] } }
```

脚本从 stdin 的 JSON 里取刚写的文件路径，按扩展名调用 formatter，并恒 exit 0——格式化是便利不是门禁，formatter 崩溃不该挡住工作（fail-open 的合法场景）。

**配方 B｜拦截向测试文件写「跳过」**——Claude Code PreToolUse，接线同配方 A（事件换成 PreToolUse，另加 `"onFailure": "block"`）：

```bash
#!/usr/bin/env bash
input=$(cat); file=$(echo "$input" | jq -r '.tool_input.file_path')
if [[ "$file" == *test* ]] && echo "$input" | grep -qE '(it\.skip|xit\(|pytest\.mark\.skip|@Disabled)'; then
  echo "拒绝：测试文件不得写入跳过标记。让测试变绿，而不是让测试沉默。" >&2
  exit 2   # 2 = 阻断且 stderr 原因回喂模型；exit 1 不阻断，是最常见的配错
fi
exit 0
```

**配方 C｜宿主无关等价物：pre-commit + CI 双保险**——任何 agent、无 hooks 的宿主均适用。

```yaml
repos:
  - repo: local
    hooks:
      - id: no-test-skip
        name: 测试文件禁止跳过标记
        entry: bash scripts/deny-test-skip.sh   # 复用配方 B 的判定逻辑
        language: system
        files: '(^|/)(tests?|spec)/.*\.(py|ts|js)$'
```

pre-commit 挡本地，CI 用同一脚本必跑——CI 在模型上下文之外，是本地 `--no-verify` 绕过之后最后的确定性防线。脚本需同时支持 stdin JSON（钩子模式）与文件参数（pre-commit 模式）两种输入。formatter、secret 扫描、依赖 diff 校验同理：本地钩子图快，CI 图全。

配方之上的两条通用法则：安全拦截型必须 fail-closed（钩子自身超时或出错也阻断，否则坏掉的钩子会静默放行一切）；审计与便利型可 fail-open（调用日志、格式化挂了不该改变控制决策）。另外，硬性 allow / deny（如禁删目录、禁读 .env）优先交给宿主权限系统——权限的优先级高于钩子的放行。

## 诚实边界

本 Skill 与一切规则文件（含本文件）都是提示层约束，无法保证被遵守。任何一条「必须」若关乎正确性，请不要依赖措辞——配置成 hooks / pre-commit / CI。报告护栏状态时区分两个概念：「已拦截」（钩子返回了阻断）与「宿主未执行」（动作确实没有发生）是两回事；没有宿主行为佐证之前，只宣称前者。
