# 简化与重构：行为保持的代码优化

> 何时读我：用户要求重构、清理、简化、精炼一段（通常是 AI 生成的）低质量代码，或抱怨代码「膨胀、重复、过度分层、看不懂」时。加功能、修 bug、写全新代码时不必读——那不是重构这顶帽子的事；途中撞见明显不合格的代码，经用户同意后可按本文件做小步机会式修整，未经同意不越界动手。本文件只回答一个问题：如何让代码更简单，同时它做的事一件不少、一件不增。

## 一、前置门：动第一行代码之前

1. **先做存活判定**。这段代码按长期维护处理吗？已有真实用户、外部集成、测试存量或明确演进意图的代码，一律走本文件的行为保持路线。理由：重写会丢掉全部能跑的边角处理与集成成果，而重写过程中你没有能力把它们全部复原。
2. **纯原型可重写，但必须显式声明**。无用户、无集成、可整体丢弃的原型，允许换提示词整段重生成——先声明「这是原型，按重写处理」，再删干净旧实现，不许新旧两套并存。拿不准就默认按长期维护处理。
3. **保护网先于结构**。动手前确认至少占其一：特征测试（把当前观察到的输入-输出对照固化成断言）、golden 输出样本、可重复执行的验证命令。什么都没有就先补：跑通主流程、把当前行为固化为测试，覆盖到主干路径即可，别为凑覆盖率耗时间——即将被重构掉的代码不值得这份投入；没有保护网的重构只是猜。
   特征测试怎么写：挑代表性输入与边界输入各几个做用例；时间、随机数、ID 这类易变值遮蔽或固定住；依赖外部服务的，先用一次真实调用把响应录下来当契约基线；断言写「现在的行为」，不写「期望的行为」——期望是猜的，现状才是网。
4. **安全发现优先于一切结构改进**。重构中撞见硬编码密钥、注入、缺授权，立即停下先修；修复属于修 bug 的帽子，单独成批后再回来继续。

## 二、行为保持铁律

- **只改怎么做，不改做什么**。返回值、副作用、错误形态、对外时序，一件不许变。测试全绿只是证据之一，真正的标准是「对外部世界可见的一切不变」。
- **一次只戴一顶帽子**。帽子只有两顶——「重构」与「加新功能」，说的是这两类改动绝不混进同一批，与主入口的审计、评审、重构三种角色是两码事。两顶帽子随时可切换；「顺手加个小功能」是把重构拖成泥潭的第一步。
- **小步走，每步可验证**。一步只做一个手法，跑一次测试再走下一步。自检判据：任何一步引入的破坏都应在几分钟内暴露；坏了两三天才发现的，不是重构，是重建。
- **「简化」与「重写」是两个动词**。简化在原结构上做减法，每一步都站在绿色测试之上；重写从空白页开始，仅限已显式声明的原型。发现自己在「简化」名义下整段替换实现，立即停：要么补重写声明，要么把改动拆小。

微型示例：卫语句提升（行为保持地压平嵌套）——

```python
# before：正常路径埋在第 4 层
def ship(order):
    if order is not None:
        if order.paid:
            if order.items:
                fulfill(order)

# after：反向条件提前返回，对外行为逐项一致
def ship(order):
    if order is None:
        return
    if not order.paid:
        return
    if not order.items:
        return
    fulfill(order)
```

## 三、双向清单：防简化不足，也防简化过头

治理 AI 代码的默认病是膨胀，但治膨胀的药过量就是删护栏。动手前后各扫一遍：

**欠简化症状（该简没简）**
- 冗余陈述：同一件事代码讲一遍、注释再复述一遍；防御代码比主逻辑还长。
- 嵌套地狱：四五层 if 套 if，正常路径不可见。
- 重复块：同一重试块、同一段校验散落多文件——跨请求无记忆的直接产物。
- 层层包装：五层调用里三层只做转发，接口复杂度与功能不相称。
- 单实现抽象：只有一个实现的策略类、无人传入的参数、从不翻转的开关。

**过度简化症状（简过了头）**
- 删掉对应真实失败的防御：发布流程消费的校验、鉴权分支、数据不变量检查。
- 把不同关注点捏进一个函数换取行数下降，读者反而更难追踪数据流。
- 为省几行合并两块独立变化的知识，制造新的耦合。
- 行数更少但更难读：嵌套三元、密集单行。可读性永远排在行数前面。
- 删掉「以后补会显著更贵」的必要准备。

**删除任何代码前过四问**
1. **有直接方案吗？** 先看库内既有代码、标准库、已装依赖；存在清晰可维护的选项就直接用，不必为「更优雅」另起炉灶。
2. **缺口具体吗？** 只有指向具体输入、具体调用方、具体失败路径的缺口才值得补；「假想的未来灵活性」不算缺口。
3. **防御对应真实失败吗？** 每个防御机制要答得出它检测什么、命中后拒绝或恢复了什么。答不出按无目的处理——但角色不明的既有保护，删除前必须先查下游消费者，缺证据不等于不需要。
4. **删掉它谁会疼？** 答得出具体流程或调用方就必须保留；只有「没有人」这一个答案才允许删。

## 四、高频重构手法表

按 AI 病灶重组。每行：手法｜对症坏味道｜动作要点｜风险点。

| 手法 | 对症坏味道 | 动作要点 | 风险点 |
|---|---|---|---|
| Extract Function 抽函数 | 超长函数、高低抽象层混杂 | 按步骤切块，父函数读成一串步骤名；新名字只说做什么 | 切太碎产出转发碎片；抽出后与原块逐段对照 |
| 卫语句提升 | 深嵌套、正常路径不可见 | 反转条件提前返回，由外向内逐层剥 | 反转时抄错边界值；每剥一层跑一次测试 |
| 内联无用中间层 | pass-through 方法、中间人类、单实现 strategy | 删纯转发层，调用点直连真实目标 | 先确认无外部调用方依赖该层签名 |
| 删投机参数与分支 | 投机泛化：无人传入的参数、空扩展点、死开关 | grep 全库确认零使用后整体删除 | 反射/DI 注册的调用 grep 不全时标注存疑 |
| 删死代码与残留 | 生成残留：未用 import、TODO 桩、注释掉的代码块 | 直接删，历史交给版本控制，不注释掉 | 「看似没人调」不等于「没人调」 |
| 合并真实重复 | 跨请求重复块、重复知识 | 同一知识三处真实重复才抽公共实现，用领域词命名 | 偶然相似强行合并制造错误耦合；合并后逐处对照 |
| 收窄浅模块 | 直通方法、直通变量、中间人、消息链、配置外推 | 接口收到覆盖当前全部需求的最简形状，复杂度压入实现 | 必要的可配置项与已发布接口别一刀切 |
| 重命名对齐行为 | 误导命名：名字与实际行为不符 | 名字陈述实际行为，隐藏副作用必须在名字中显形 | 全库一次替换干净，不留双名并存 |
| 魔法值具名 | 写死的数字里压着业务规则 | 提为命名常量；规则随值走时升级为值对象 | 数学恒等值与刻意具体的测试数据不在此列 |
| 引入参数对象/值对象 | 长参数列表、数据泥团、基本类型偏执 | 总是结伴出现的值捆成类型，校验跟着类型走 | 只出现一次的组不值得建类型 |
| 拆解上帝类 | 上帝类、发散式变化 | 按变更理由聚类方法字段，逐群搬移 | 每搬一群跑全量测试；中间状态保持可跑 |
| 集中判别 | 重复 switch、补丁堆积 | 同一类型标记的分支收拢到一处（表驱动或多态） | 系统边界处的穷尽 switch 是合理形态，保留 |
| 预检查替代异常 | 可定义掉的错误、过度防御 try | 用语义保证消灭异常条件 | 常改变可观察行为——若变，转修 bug 帽单独成批 |
| 拆阶段/拆循环 | 一段代码混杂解析、计算、落盘 | 按阶段切开，中间产物显式成数据结构 | 中间结构别顺势升级成公共 API |

微型示例：删投机参数——

```python
# before：cache_size 与 observer 是「预留未来」，全库无人传入
def load_config(path, encoding=None, cache_size=None, observer=None):
    if encoding is None:
        encoding = "utf-8"
    return parse(read(path, encoding))

# after：投机参数删除，默认值内联
def load_config(path):
    return parse(read(path, "utf-8"))
```

## 五、抽象时机判据

- **同一知识三处真实重复才抽**。判据是知识不是文本：改一处、不改其余即为错的，才是真重复；碰巧长得像但会独立演化的（如客户端与服务端校验），保持分离。
- **抽之前先 grep 既有 helper**。库里已有同职责符号就直接调用，并指到既有路径为证；找不到再造。AI 重复高发的成因之一正是写前不读。
- **热点路径例外**。git log 高频变更区允许提前设计接口形状——那是对确定变化的准备，不是投机；冷区宁可容忍重复。
- **「为未来灵活性」的抽象推定有罪**。要建就得辩护：说出这个抽象的第二个真实消费者是谁。说不出来就不建。

## 六、大规模改写的安全网

- **先冻结行为基线**：代表性输入-输出对（golden 样本）、全量测试结果、关键接口的响应形状。基线必须机器可读、可重跑——手工敲的对照表什么也证明不了。
- **超过约 800 行的改动先出拆分方案，不动代码**：切几批、每批动哪些文件、批间什么依赖；每批独立可验证、可回滚、一类改动一个 commit。
- **绞杀者式增量替换**：新旧并存时先建一层接缝，把调用方一批批迁过去，每迁一批对照基线；全部迁完再删旧实现。过渡期双轨不是浪费——它把一次大爆炸的风险换成多次小验证。
- **任何中间批次停下时系统必须能跑**：可构建、可发布、测试可执行。

## 七、收尾验证

- **每批改动后跑全量测试并对照基线**，命令与输出留档，按证据分级标注；机械数字必须能追溯到命令。不接受「测试应该过」这类措辞。
- **逐行读删除的行**。护栏被顺手拔掉时，diff 表面与正常精简无从分辨，代价要到运行时才暴露——这是 AI 最隐蔽的坏味道。被删的防御分支逐条过第三、第四问。
- **测试文件的改动单独 diff 并写明理由**。为让代码通过而放松断言、删测试、跳过测试，一律不允许；特征测试的增删也要能说出所以然。
- **浏览快过理解就停**。逐行慢读才算验证；飞快掠过的改动等于从未检查。
- **按风险分级收口**：认证、支付、数据访问、并发等高危路径上的批次，交人工逐行复审后才算完。

## 八、一批改动的验收清单

每批 commit 前逐项打勾，打不满勾不算完成：

1. 帽子唯一：本批只有结构移动，零功能增删。
2. 保护网在位：动手前特征测试或基线已存在且全绿。
3. 新鲜证据：本会话跑过全量测试，与基线零差异，输出已留档。
4. 删除行已读：每一行被删代码都逐行看过，确认不是护栏或边界分支。
5. 测试改动已申报：测试文件若有改动，理由单独列出，断言无放松。
6. 抽象有据：新增抽象满足三处真实重复或热点路径判据。
7. 净变化可解释：删的行、增的行各自对得上所用手法的动作要点。
8. 批次自包含：一个 commit 一类改动，每批控制在一屏到几屏，评审者 15 分钟内能看完。
