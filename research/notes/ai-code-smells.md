## 1. 重复代码 / 复制粘贴（Duplication & Copy-Paste）
- **定义**: 同一逻辑多次复制而非抽象复用；inline 重复块暴涨。
- **表现**: 5+ 行重复块成倍增长；"复制一段再改两行"；相似 helper 每个文件一份。
- **原因**: LLM 逐任务生成、无跨会话记忆；上下文窗口内看不到已有实现；生成"能跑"优先。
- **证据**: GitClear——重复块 8 倍增长、copy/paste 首超 moved（§0）。
- **治理**: 项目内重复检测（jscpd/copy-paste-detector）进 CI；要求 agent 生成前先检索现有符号；Skill 规则"先查库再写新函数"。

## 2. 错误静默吞掉（Silent Error Swallowing）
- **定义**: 异常被捕获后既不上抛也不有意义处理。
- **表现**: `except: pass`；空 catch 块；catch 里只有 `console.error` 不 rethrow；`.then()` 无 `.catch()`；`throw new Error("Something went wrong")` 式含糊报错。
- **原因**: 训练语料充斥低质量示例；模型倾向"让程序继续跑"而非正确传播失败；对失败路径语义无把握时的妥协。
- **证据**: vibecheck 规则目录（no-empty-catch / no-pass-except / no-bare-except / no-vague-error / no-swallowed-promise）https://github.com/yuvrajangadsingh/vibecheck；CodeRabbit——异常路径缺口 ≈2×。
- **治理**: lint 硬规则（bare except / empty catch 报 error）；Skill 要求"异常必须：处理、上抛或显式注释为什么忽略"。

## 3. 过度防御性编程（Defensive Over-Programming）
- **定义**: 对不可能为空的输入做无意义空值检查；把整段逻辑包进 try/except；到处 `if x is None` 兜底。
- **表现**: 层层 None/undefined 检查掩盖真正的类型错误；防御分支掩盖 bug 让其静默通过；"防御性"代码反而吞掉该早失败的错误。
- **原因**: 模型在不确定上下文时选择"最安全"的保守输出；对 API 契约不了解于是全量防御；训练数据中教程式防御代码偏多。
- **证据**: HN 讨论（duskwuff: 模型偏好高概率样板输出）https://news.ycombinator.com/item?id=41677207；vibecheck（no-py-log-swallow 标注"AI 痕迹"）。**张力提示**: CodeRabbit 同时发现 AI 代码"缺少 null 检查/早返回/守卫"≈2×——即 AI 在"该防御处不防御、不该防御处乱防御"，核心是**防御放错位置**，Skill 应写"契约处防御、内部信任类型"。
- **治理**: 强类型边界（入口 validate，内部直传）；区分"边界防御"与"内部兜底"两条规则。

## 4. 幻觉 API / 幻觉依赖（Hallucinated APIs & Packages）
- **定义**: 调用不存在的方法、参数、CLI 标志或 import 不存在的包。
- **表现**: 编造 npm/PyPI 包名（slopsquatting 风险）；不存在的库函数参数；过时 API（训练截止后的破坏性变更）。
- **原因**: 事实冲突型生成错误；对版本/生态记忆模糊；概率上"像真的"接口名。
- **证据**: arXiv 2406.10279（5.2%/21.7%，205k 包名）+ 2608.23897（slopsquatting 检测）；vibecheck（no-hallucinated-import-js/py）；HN（Pulumi AI 污染搜索结果，模型互相训练的 slop 循环）https://www.theregister.com/2024/05/01/pulumi_ai_pollution_of_search/。
- **治理**: 依赖安装前 registry 存在性校验；锁依赖白名单（AGENTS.md 里列允许的包）；编译/lint 挡幻觉 import。

## 5. 嵌套过深（Deep Nesting）
- **定义**: 4 层以上 if/for/try 嵌套，不用早返回/卫语句。
- **表现**: 金字塔回调；嵌套三元；if 里 if 里 else。
- **原因**: 模型线性"接着写"而不回溯重构控制流；上下文越长越不敢提前 return（怕丢状态）。
- **证据**: vibecheck（no-deep-nesting，4+ 层告警）；HN 41677207 多条评论描述 AI 生成金字塔代码。
- **治理**: 静态复杂度阈值（cognitive complexity / nesting depth）进 CI；Skill 规则"超过 2 层嵌套必须改卫语句"。

## 6. 啰嗦冗余与废话注释（Verbosity & Junk Comments）
- **定义**: 代码比必要的长；注释复述代码本身；装饰性分割线与旁白。
- **表现**: `// initialize the counter`；`// Step 1: ...` 编号步骤注释；`// ========` 分割线；`// This function handles...` 旁白式 docstring；20 行"小作文"注释；`// Generated by ChatGPT` 署名；对仗式 try/except 样板。
- **原因**: 模型偏好高概率 token（样板、getter/setter、docstring 模板）；用注释"表演"在做事；语料中教程代码带步骤注释。
- **证据**: vibecheck（no-obvious-comments / no-step-comments / no-section-dividers / no-narrator-comments / no-ai-attribution）；HN（drewg123: "crack down on 20-line essay comments"）https://news.ycombinator.com/item?id=49934037；HN 41677207（duskwuff 概率偏置分析）。
- **治理**: 注释规则"解释为什么而非是什么"；禁止步骤编号注释；Skill 里给 good/bad 注释对照示例。

## 7. 命名退化（Vague & Inconsistent Naming）
- **定义**: 泛化、含糊、同义反复的命名；同一概念多种叫法。
- **表现**: `data`, `result`, `temp2`, `processData`, `handleStuff`；`utils.js` 万物桶；同一实体 3 种拼写。
- **原因**: 缺项目词汇表；模型按局部上下文最"通用"的命名生成；跨文件无一致性记忆。
- **证据**: CodeRabbit——命名不一致 ≈2×；Qodo——缺上下文是头号质量根因（44%）。
- **治理**: 项目 glossary/UBI 词汇表进 AGENTS.md；review 时检查命名与领域词一致；`no-magic-strings`。

## 8. 过度抽象 / 投机泛化（Speculative Generality & Over-Engineering）
- **定义**: 为想象中的未来需求引入配置项、接口、工厂、策略层。
- **表现**: 单实现 Interface + Factory + Builder 全家桶；只有一种后端却抽象出 Provider 层；`config` 传 12 个可选参数；"以防万一"的 feature flag。
- **原因**: 训练语料中企业级 Java/设计模式教程偏多（HN 评论：语料里工厂/建造者样板泛滥）；模型模仿"看起来专业"的高频结构。
- **证据**: HN 41677207（derefr: 语料风格决定输出风格；srinathkrishna: 工厂/建造者滥用）；vibecheck god-function 类规则。
- **治理**: YAGNI 规则"第三个实现出现才抽象"；Skill 检查"接口只有 1 个实现且无测试替身需求 → 删"。

## 9. 超长函数 / 上帝函数（God Function）
- **定义**: 单函数超长（80+ 行）、多职责。
- **表现**: 一个 handler 从路由到 SQL 到 HTML 全干；几十个参数对象。
- **原因**: agent 一次任务一口气生成不拆分；"再补一点"式追加导致函数无界生长。
- **证据**: vibecheck（no-god-function >80 行）；arXiv 2511.15817 对 LLM 生成代码 smell 的度量为 long method 类最普遍。
- **治理**: 函数长度/职责 lint；Skill 规则"一个函数一个抽象层、一个职责"。

## 10. 桩代码与死代码（Stubs & Dead Code）
- **定义**: 占位实现、假 TODO、生成后被遗弃的分支。
- **表现**: `throw "not implemented"` / `NotImplementedError` 进生产；`TODO: implement`；写了但从未调用的 helper；被新方案替代却没删的旧路径。
- **原因**: agent 分步生成中途放弃/换方案不清理；模型对"完整性"的表演（生成一个空壳显得功能齐全）；churn 高企的伴生现象。
- **证据**: vibecheck（no-stub-function / no-ai-todo）；GitClear（"departed" 代码与 churn 数据，§0）。
- **治理**: CI 检测未引用导出；规则"任何 TODO 必须带 issue 链接和日期"；完成后跑死代码清理（knip/ts-prune/vulture）。

## 11. 类型逃逸（Type Erosion）
- **定义**: 用 `any`/类型断言/`# type: ignore` 绕过类型系统。
- **表现**: `as any`、`as unknown as T` 双重断言；无差别 `# type: ignore`；`def f(x)` 无注解。
- **原因**: 模型为了让代码"编译通过"走捷径；类型不确定时选择压制而非修正。
- **证据**: vibecheck（no-ts-any / no-double-assertion / no-type-ignore-blanket）。
- **治理**: strict 模式 + lint 禁裸 ignore；Skill 规则"先修类型再谈运行"。

## 12. 高 Churn / 即写即弃（Write-Then-Revert Churn）
- **定义**: 新增代码短期内被大改或删除。
- **表现**: 一次会话反复重写同段；merge 当天就 revert；功能"完成"但之后两周持续返工。
- **原因**: 快速生成降低了"写"的成本也降低了"想"的成本；spec 不清导致先写后改；多轮对话中模型推翻自己。
- **证据**: GitClear——2024 年 4.1% departed，预计 2026 翻倍；SO 2025——45% 称调试 AI 代码更耗时。
- **治理**: 先 plan/spec 后生成（HN 46255285 高赞共识）；小批量提交；diff 审查聚焦"这行三天后还会在吗"。

## 13. 上下文盲 / 无视项目约定（Context Blindness）
- **定义**: 不了解项目既有约定、架构、依赖，生成"通用 StackOverflow 风格"代码。
- **表现**: 引入项目已有功能的第三方库；不遵循项目错误处理/日志/目录约定；技术栈漂移（顺手引入新框架）；风格与周围代码割裂。
- **原因**: 上下文窗口限制；agent 未读关键文件；模型默认走训练先验而非项目现状。
- **证据**: Qodo（65% 错过上下文 / 44% 质量下降根因）；HN 46255285（"context is king"）；HN 49934037（规则文件+skills 做法）。
- **治理**: AGENTS.md/CLAUDE.md 明确约定与依赖白名单；生成前强制检索代码库；把 lint 规则喂给 agent。

## 14. 弱测试 / 假测试（Illusion of Tests）
- **定义**: 测试存在但不验证任何有意义行为。
- **表现**: 只测 happy path；`assert result is not None`；mock 一切后测 mock；生成测试与实现同源（同一个模型的同一误解，自证清白）；覆盖率虚高。
- **原因**: 测试由同一模型生成，共享同一错误认知；模型迎合"覆盖率指标"而非验证语义。
- **证据**: HN 49934037（tmarice: "LLM 生成的测试相当差…除了 1==1 什么都没测"）；Qodo（AI 测试的上下文缺失）。
- **治理**: 测试先行或人写断言、AI 只填骨架；变异测试（mutmut/Stryker）验测试有效性；禁止 AI 同时写实现和验收测试却不经人审。

## 15. 安全捷径（Security Shortcuts）
- **定义**: 把"能跑"的 demo 习惯带进生产路径。
- **表现**: 硬编码 API key/密码；`eval`/`exec`/`shell=True`；SQL 字符串拼接；`innerHTML`/`dangerouslySetInnerHTML`；secret 进日志。
- **原因**: 训练语料大量 demo/教程代码无安全卫生；模型无威胁模型概念。
- **证据**: Veracode 2025（45% 样本含漏洞，转引）；CodeRabbit（安全问题 2.74×）；vibecheck Security 组 6 条规则。
- **治理**: secret 扫描（gitleaks）+ SAST 进 CI；规则"密钥只从 env 读、SQL 必须 prepared、禁止 eval 系"。

## 16. 调试残留（Debug Residue）
- **定义**: 调试用输出/临时代码遗留在生产代码。
- **表现**: `console.log`/`print`/`debugger`；注释掉的旧实现成片留存。
- **证据**: vibecheck（no-console-pollution / no-py-print）。
- **治理**: lint 禁裸 print/log；提交前自动清理规则；`--fix` 自动删除。

## 17. 可读性整体退化（Readability Decline）— 结果性指标
- CodeRabbit: 可读性问题在 AI 贡献中 **3×**——是所有类别中最高的相对增幅，坏味道清单的最终苦果。治理以以上 1-16 为杠杆，用可读性指标（可读性 lint、cognitive complexity）做回归验证。

## 18. 治理总策略（跨类别，来自证据共识）
1. **机检清单化**: 把 1-16 落成 lint/静态规则（vibecheck 模式，40 条规则零配置），AI 生成代码过同一套门禁。
2. **上下文工程**: AGENTS.md 写明约定、依赖白名单、命名词汇表（Qodo 44% 根因；HN 共识）。
3. **流程隔离**: 生成与审查分离——"不能 AI 写码又 AI 验收同一个模型自审"（HN 41677207 thelostdragon；49934037 verdverm 用另一模型查 slop 模式）。
4. **小步生成 + 人在环**: plan→一步→review→course-correct（HN 46255285 多条高赞）。
5. **重复与死代码专项**: cpd + 死代码工具进 CI，对抗 GitClear 8× 重复趋势。
6. **对厂商研究保持怀疑**: jadarma 的统计批判（自评指标、无显著性、幸存者偏差）——Skill 中引用质量数据须看方法学。
